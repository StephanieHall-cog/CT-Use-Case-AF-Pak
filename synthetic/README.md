# Synthetic supplements
Fictional persons/orgs/events in the same JSON shape as `raw/extractions/*.json` (set `"episode": {"idx": null, "title": "SYNTHETIC: <scenario>"}`).
Build with `python3 scripts/build_db.py --synthetic synthetic/*.json`. Entity ids are prefixed `S` and rows carry `dataset='synthetic'`
so a GUI can badge them. Rules: fictional names only; a synthetic person may be *linked* to a real organization or place, but never
to a real person as family/deputy/etc. without a visible synthetic flag on the edge (the `dataset` column on `relationships`).

## Target-tracking demo (`targets_demo.json`, `sites_reference.json`)
Generated by `python3 scripts/synthetic_targets.py` (deterministic). Adds `scenario_kind: "targets"` sections that `build_db.py` loads
into `target_cards`, `selectors`, `selector_links`, `location_hits` and `event_geo` (attacks with coordinates); `sites_reference.json`
is loaded into `sites` as real public-reference locations with approximate coordinates (`verified=0`). All identifiers are fictional
and drawn from non-allocated ranges (555 phone blocks, IMSI …99…, IMEI TAC 00000000, example.com). See `docs/gui-plan-v2.md` §6.
